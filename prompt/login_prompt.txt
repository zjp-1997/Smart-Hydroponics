# 四、登录流程设计


请按照企业级流程设计。


完整流程：


```
用户输入账号密码

        ↓

Controller接收请求

        ↓

参数校验

        ↓

查询用户

        ↓

校验用户状态

        ↓

BCrypt密码验证

        ↓

生成JWT Token

        ↓

保存登录状态

        ↓

查询用户权限

        ↓

返回登录结果

```

# 五、JWT设计要求


设计 JWT Token。


Payload 至少包含：


```json
{
    "userId":10001,
    "username":"admin",
    "role":"ADMIN",
    "iat":123456,
    "exp":123999
}
```


需要说明：

- Token生成方式
- Token有效时间
- Token刷新机制
- Token失效处理


---

# 六、Redis设计


登录成功后：

使用 Redis 保存用户登录状态。


例如：

Key：

```
login:user:{userId}
```


Value：

```
token
```


作用：

- 强制下线
- 单点登录控制
- Token注销


---

# 七、接口设计


请按照 RESTful 标准设计接口。


## 登录接口


请求：

```
POST

/api/auth/login
```


请求参数：

```json
{
    "username":"admin",
    "password":"123456"
}
```


返回：

```json
{
    "code":200,
    "message":"登录成功",
    "data":{
        "token":"",
        "refreshToken":"",
        "userInfo":{}
    }
}
```


---

## 退出登录


接口：

```
POST

/api/auth/logout
```


功能：

- 删除Redis Token
- JWT失效


---

## 获取当前用户


接口：

```
GET

/api/auth/info
```


返回：

当前登录用户信息。

# 十、安全设计


必须考虑：


## 密码安全

要求：

使用：

```
BCryptPasswordEncoder
```


禁止：

```
MD5
SHA1
明文密码
```


---

## 防暴力破解


增加：

- 登录失败次数限制
- IP限制
- 验证码机制


例如：

Redis记录：

```
login:error:{username}
```


超过次数：

锁定账户。


---

## Token安全


考虑：

- Token过期
- Token刷新
- Token注销
- Token盗用


---

## 数据安全


考虑：

- 密码脱敏
- 用户信息脱敏
- SQL注入
- XSS攻击
